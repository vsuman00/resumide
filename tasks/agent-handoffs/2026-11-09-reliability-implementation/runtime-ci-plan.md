## Exact execution boundaries and rollback

The existing API synthetic-account authorization can support only admitted exact-owner cases. A protected run needs the exact Supabase URL, publishable key, server secret and private bucket, scoped environment access, a reviewed SHA and an owned ledger. Their GitHub availability/protection has not been checked or assumed. Keep real provider keys absent; preserve original `HOME` and private-mode dotenv suppression. Missing credentials must fail admission before fixture creation.

Native SQL/CAS additionally need an explicitly bound managed PostgreSQL connection, verified TLS material, installed compatible `psql`, schema revision and sufficient narrowly reviewed privileges for current auth/RLS fixture SQL. API keys alone do not supply that connection. Do not infer native-host identity from a similar hostname or use a transaction pooler without proving required session/transaction behavior.

Global analysis/privacy/retention claims and real R11 polling require an actually available isolated synthetic managed target with exclusive queue/worker ownership, no unrelated jobs and a reviewed workload/cleanup budget. None is established here. On a shared project, owner filtering after a global claim is prohibited. An exact-scoped development harness can provide narrower evidence but cannot close the unchanged global lifecycle gate.

R22 separately needs the new guarded `scripts/verify-managed-restore.ts`, exact approved source/destination, current backup/private-object capability, native dump/restore tools and an explicit restore/DDL/retention packet. Never restore over the configured shared project or use the Docker driver. Preserve populated historical digest, replay, score, authoring, immutability, RLS and permission assertions; actual RPO/RTO evidence remains open. No target, hosted DDL, provisioning, spend or protected-secret configuration is authorized implicitly by this document.

Rollback is to stop the owned runner, retain failed receipts and reconcile only ledger-owned resources. Keep managed gates blocked until evidence exists; never restore prohibited Docker-DB commands or loosen thresholds to recover a green badge.
