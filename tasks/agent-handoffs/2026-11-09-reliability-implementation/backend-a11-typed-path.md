`typed-authoring-contract.ts` exports strict selection, binding, policy, target, transformation, patch, command, proposal, workspace and receipt schemas/types. The request ID must equal the idempotency key; that key is excluded from semantic bytes and correlated separately in the receipt.

The initial portable transform substitutes only a leading Built/Created/Developed action in supported lowercase or title case. The remaining bytes stay identical. The actual writing-support verifier must also admit the replacement. Every patch retains the actual witness basis, full before/after text, support and null score/value deltas. Full page coverage and supported evidence policy are required; calibration and requirement-review blockers alone do not prohibit bounded editorial support.

Source citations are current tuples; historical citations never become quotations for changed text. The stored JD expression stays unchanged, including unknown expressions with separately derived duration subjects. Editorial relevance does not establish the stated duration, proficiency or qualification.

It bounds transport waiting and final-read cancellation and withholds stale or invalid output. `applyTypedAuthoring` rederives the original captured command against an owned selected snapshot, preserving original heads for SQL exact replay rather than rebasing them. Receipt validation correlates the command hash/key, base/JD versions and revisions, action and result. Acceptance requires the final confirmed child at base revision plus two; rejection retains the base revision/version. The SQL lane owns the atomic edit -> confirm transaction.
