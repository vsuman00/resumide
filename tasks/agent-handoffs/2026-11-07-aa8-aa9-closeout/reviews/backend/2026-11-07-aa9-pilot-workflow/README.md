# Operational local advisory workflow

Owned files: `app/lib/server/pilot-workflow.ts` and `tests/unit/pilot-workflow.test.ts`. The workflow runs locally with injected trusted callbacks and ephemeral state; it does not create hosted persistence or authorize external contact. No DB, environment, push or deployment operation occurred. The owner's explicit STOP ANY DEPLOYMENT restriction remains in force; only the coordinator handles the separate requested GitHub scope.

`createPilotWorkflow(protocol, runtime)` validates a server-owned protocol, allowlisted actor identities/roles and participant/source bindings. Its controller exposes strict versioned `execute(command)` and a server-only sanitized `auditSnapshot()`. A single in-flight guard and expected revision prevent concurrent or stale execution. Completed commands have bound idempotency keys; changed payloads cannot reuse them. Accepted actions append immutable hash-chain events. Returned snapshots are copies. The bound is 4,096 events, 256 subjects, 64 actors and 16 adapter attempts per command. Installed trusted callbacks own their I/O deadlines; the controller itself performs no network I/O.

A notice handler must return a receipt before any advisory read or human decision. The deterministic rubric reader is the only numeric source; commands cannot supply scores or prose. Candidates can read their own noticed advisory. Decisions require an allowlisted human owner/adviser and a rationale reference, and preserve the exact rubric/source binding. Corrections and appeals have explicit open/resolve cases and retain original events. Corrections require old/new source hashes and trusted update authority, and invalidate previous rubrics. Expiry, revocation, stop and source drift deny cached as well as new reads.

Vendor observations call the actual installed adapter with per-attempt request IDs. Named external adapters require separate trusted target authorization; the current synthetic path cannot become an external observation by relabelling JSON. Errors use fixed codes. Missing latency/cost stays unknown rather than becoming zero. Missing monitor policy, malformed output or threshold breach stops further attempts and future decisions; requested/completed counts disclose interruptions. Manual stop and rollback bind the previous policy version. Retention deletion requires an actual trusted handler receipt; failed verification appends an honest failure and revokes access without claiming deletion.

Actual verification: 17 behavioral tests pass with Node.js 22.23.4. TypeScript, ESLint, Prettier and diff checks pass. Two focused RED/GREEN regressions reproduced malformed adapter output leaving a run active and a cached read bypassing the in-flight deletion guard; both are fixed. Failed deletion now leaves an auditable revoked state. Tests also exercise notices, human overrides, immutable correction/appeal history, source authority, cached-read expiry/revocation, actual repeat calls, stale/concurrent rejection, external default denial, stop/rollback and hash-chain integrity.

This is operational software and synthetic execution evidence, not a recruiter/customer pilot, independently human-validated result, named-vendor compatibility claim, hosted deletion receipt or production activation.

Independent frontend review found an asynchronous freshness gap. Two new tests reproduced an expired/changed actor receiving a rubric after loading, and revoked external authority allowing a second attempt. The fixed code rechecks trusted actor/time after loading and target authority around every attempt; completed receipts remain recorded and interrupted runs stop. Both regressions pass. No other workflow scope changed.
