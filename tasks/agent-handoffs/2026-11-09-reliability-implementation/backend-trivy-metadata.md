## Strict JSON contract

Before recursive standard parsing, a lexical preflight bounds raw nesting to 32 and counted containers/keys/values to 4,096. Standard json.loads remains the syntax parser. Object hooks reject duplicate decoded names and more than 128 members. Arrays are limited to 128 entries, keys 128 UTF8 bytes and strings 16 KiB UTF8. Unicode decoding is strict; escaped unpaired surrogates reject. Numeric tokens are limited to 32 characters; integers must be exactly interoperable within ±9,007,199,254,740,991. Non-finite constants and float overflow such as 1e999 reject. Trailing data and malformed syntax reject. These are concrete metadata-processing limits, not adopted Sigstore signature semantics or a promise that every future bundle format is accepted.

The recognized media/content shapes are finite maintained bundle encodings, messageSignature with SHA2_256 or a DSSE envelope whose digest is labelled not-stated. A reported message digest requires a nonempty digest field; reported DSSE signature presence requires at least one nonempty signature field. These are field-presence checks, not base64, DER or cryptographic verification. Unexpected shapes/algorithms fail closed. DSSE acceptance here stages an untrusted public JSON asset only; the later crypto source must choose a reviewed supported path after observing the real asset. No arbitrary JSON string is logged as a media type, algorithm, URL exception or certificate value.

## Files, atomic publication and hard timeout

Parent components are opened without following symlinks. The new private directory is bound by owner/mode/device/inode; fixed files use exclusive nofollow creation and regular/nlink checks. Existing cache/output/foreign or hardlinked state is rejected and preserved. Bytes are written to the fixed owned temporary, fsynced, read back through the bounded descriptor and rehashed. Bundle mode becomes 0444 before no-overwrite atomic publication; the temporary hardlink is then removed and final nlink 1 verified. The controlled two-link interval is inside the new 0700 directory; an interrupted operation is never a successful/admitted terminal output. Receipt publication is atomic too, including its first write. Successful normal completion leaves exactly the receipt and bundle.

No broad cleanup occurs. Only a helper-created partial with the exact recorded inode may be unlinked on a normal failure. A hard kill can retain partial files; preserve them for exact scoped inspection rather than deleting/retrying automatically.

The watchdog cannot depend on receipt/stdout I/O: it exits 124 directly at the deadline. This bounds blocked DNS/TLS/request/read or staging even when output I/O is blocked. It can leave an absent or IN_PROGRESS receipt, or a staged receipt if the deadline wins the final publication race. **Any nonzero/unknown process exit invalidates a staged status.** Treat exit 124 without a normal terminal result as HARD_TIMEOUT_UNKNOWN. Do not infer zero HTTP activity from initial progress counters. `requiresNormalExitZero:true` is mandatory; a staged receipt alone is never PASS. Normal caught failures emit sanitized error enums and best-effort atomic failure receipts. Raw exceptions and signed redirect queries are not retained.
