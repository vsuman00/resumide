## Resulting behavior

The server uses imported expected readiness pins and the actual supplied Supabase RPC interface. It releases a bounded workspace only after owned source/version checks, readiness admission and a complete final owned reread. Disabled preparation performs no extra work or serialization. Acceptance/rejection verifies the ORIGINAL captured pair before invoking the independent Native writer; later current heads are never substituted into a retry.

The private POST resource at `/analysis/:id/author/clause-order` requires authentication, same origin and the existing scoring/authoring/typed-authoring flags. It rejects unexpected fields, duplicate JSON/form keys, unsupported bodies and oversized or late requests. It requires a separate review acknowledgement for acceptance and returns only strict v2 receipts or bounded error envelopes. The default-off flags are unchanged and the migration grants no execution on the Native writer.

The page mounts the controlled bridge with a stable owned source even when a new workspace is unavailable. Original reviews and exact command keys survive same-source head changes and unknown outcomes. Cross-source/access loss clears them. A later known error does not silently erase a previously uncertain decision or undo. There are no automatic retries or new keys. Current diagnostics can be refreshed explicitly while the captured review remains pinned.

Undo loads the actual owned accepted canonical version and owner-filtered event, validates its original v2 command and receipt, invokes the existing guarded rollback to the event's original base, and verifies the resulting undo event, command, version, revision and key before wrapping an undo2 receipt. The old internal rollback acknowledgement is never accepted as a public receipt downgrade. The complete undo flow has a five-second deadline and propagates SDK cancellation; an uncertain write stays retryable with its original key.

The failed receipts and author fixture corrections are preserved separately.
