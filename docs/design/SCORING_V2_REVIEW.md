# AA4 scoring diagnostics and legacy presentation

Status: local engineering implemented under owner-approved E-004. Numeric policy activation and formal Gate AA4 remain open.

The private `/analysis/:id/score` read model combines an immutable document-evidence attempt, a selected canonical resume version, a selected JD requirement version, an exact draft policy ID and server-owned declared page metadata. It creates a deterministic fingerprint and diagnostics; it writes no score/history rows. The existing canonical/JD histories and privacy export remain the replayable inputs. With the same producer, policy and inputs, a populated restore test regenerates the same diagnostics. Declared page metadata is checked live; changing it changes the input fingerprint and page observations. This read model is not an archive of previously published scores.

Diagnostic producer `score-v2/1.0.2` separates an exact recorded owner/value declaration from source citation and skill proficiency. Declared uncited matches and declared listed skills remain `not_evaluated` with the remaining evidence or proficiency/duration reason; they do not request the same recorded confirmation again. Citation eligibility must belong to that same exact declared fact. Role/date source requirements, calibration blockers and withheld numerical dimensions are unchanged. The producer is bound into output and fingerprint, and the validity report derives its version from generated output. Historical envelopes keep their original producer semantics; regenerating historical inputs identifies the current producer rather than claiming byte-identical replay across producer versions. No scoring-policy adoption, score persistence, canonical/suggestion producer or SQL change follows. See the [repair evidence](../../tasks/agent-handoffs/2026-11-09-reliability-implementation/jd-review-closeout.md).

`SCORING_V2_ENABLED` defaults to false. Enable it only for local review alongside the evidence/canonical/JD flags. No migration or deployed worker setting changes are needed for these diagnostics. Authentication precedes privileged reads; ownership, membership, active source, deletion requests and head versions are checked before and after computation. Historical selectors are UUIDs; other parameters and client weights/policies/identity are rejected. Private responses use no-store and noindex headers. Writes receive 405. Removed sources and cross-owner versions receive 404, moving/stale heads 409, invalid inputs 422 and unavailable storage 503.

Stored `requirements/2.0.0` JDs now use the owned relationship context and `score-v2/typed-1.0.0` diagnostics. The repository checks the selected resume/JD pair, source integrity and declared page metadata, then repeats owned reads and head/content checks after computation. Missing or unsafe context stops the check. Moving inputs return 409. Typed observations remain separate from authoritative numeric scores. Representative quality validation and scoring-policy adoption remain open. [Typed consumer closeout](../../tasks/agent-handoffs/2026-11-09-reliability-implementation/a10-typed-consumer-closeout.md)

Legacy diagnostic producer `score-v2/1.0.3` checks the original JD quote before using its stored minimum tenure. It compares an inclusive whole-year minimum for general experience. It leaves upper bounds, strict and exact comparisons, fractions, alternatives and subject-specific tenure for review. The producer version is part of the input fingerprint. Saved JD rows and historical envelope readers retain their original versions. [Regression evidence](../../tasks/agent-handoffs/2026-11-09-reliability-implementation/cr-a15-legacy-tenure-quote.json)

Typed score producer `score-v2/typed-1.0.1` recognizes a single `•`, `-` or `*` followed by horizontal whitespace at the start of a JD line. The coverage review applies the existing rules for alternatives, conjunctions and explicit year bounds after that marker. It retains the exact marker, clause and operand spans and keeps negated, ambiguous and unmapped clauses unresolved. The review reading is versioned separately from the saved JD. [Regression evidence](../../tasks/agent-handoffs/2026-11-09-reliability-implementation/cr-a08-typed-jd-list-formatting.json)

Coverage policy `typed-fact-coverage/1.2.0` reads standalone Preferred Skills and Mandatory Skills headings. The score review cites the exact heading when a qualification inherits its scope. Explicit importance, conflicts and negation keep their clause-level handling. The saved JD remains available for replay with its original producer. [Regression evidence](../../tasks/agent-handoffs/2026-11-09-reliability-implementation/cr-a08-typed-jd-skills-headings.json)

All three authoritative dimensions remain null. They are ATS Compatibility, Required Job Alignment and Preferred Job Alignment. Calibration, weights, coverage floors and bands are unavailable. Recovery coverage describes where text was observed, not calibrated extraction accuracy. Confirmation records owner review but cannot clear calibration/source-quality blockers. Unsupported domain/locale inputs stay unsupported, and Application Readiness remains disabled.

Local PostgreSQL verified selected JD and canonical versions, historical relationship reads, and restore. The scoring engine read two saved Python experience bounds over the same overlapping intervals. It calculated the interval union, kept the results for review and withheld all three authoritative dimensions. Six bounded technical traces describe recovered pages, recognized sections, contact candidates, date order, bullet duplication and qualified layout evidence. Rule credits are diagnostic observations, never activated policy contributions. Layout remains not evaluated when no qualified geometry is available. Illustrative weighted normalization is isolated from production scoring and tests the AA0 60/75/coverage examples, justified inapplicability, unknown critical checks and zero denominators.

Alignment preserves required/preferred/contextual/unknown importance. Exact typed requirements group once independently of supplied dedup labels. Conflicting importance, inferred/model-proposed clauses, unpaired dates, unsupported equivalents and missing evidence remain unknown. Confirmed full ISO date ranges linked to software roles use the union of overlapping intervals; ambiguous years and Present dates do not create inferred duration. Candidate observations are explicitly separate from evaluated requirement states; all positive alignment remains not evaluated pending source/domain/policy validation.

New model requests use a strict score-free prose schema with exact resume quotes. Unmatched quotes are excluded. Provider output persisted in AI-run history has no numeric rating fields. The existing feedback envelope keeps zero compatibility placeholders for qualitative categories, explicitly tagged `deterministic_baseline_no_model_ratings/1.0.0`; the UI/report hides these placeholders and shows cited prose. The overall baseline comes entirely from existing deterministic rules. Completed historical records are never reprocessed; original values, dates and recorded versions remain unchanged and are labeled legacy, without v2 comparison. Unknown historical scoring versions remain unknown. The original numeric output schema remains available for historical compatibility only.

The offline validity harness measures deterministic replay, synthetic-name invariance, repeated clauses, skill/bullet stuffing, injection rejection, coverage and latency. A separate strict measurement helper implements tie-aware Spearman, seeded case bootstrap percentile intervals, MAE, RMSE and per-segment coverage/error. Mathematical synthetic tests validate these estimators; no real reviewed ratings are claimed. Benchmark engineering mode passes its known synthetic checks; release mode emits a blocked receipt and exits 1 while representative/expert/domain/calibration/comprehension obligations remain open.
