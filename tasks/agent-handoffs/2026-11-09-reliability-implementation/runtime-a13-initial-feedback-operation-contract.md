No application or migration source, tests, SQL parser/execution, database, services, providers, environment or Git operations are part of this allocation.

## Frozen inputs and authority

Keep the original scoring-input foundation and stored-source guard unchanged: migration `20261115064102` SHA `9e857437bbd3d5995d7942b365406f9eb9f96197d3495853747cf950fdb1c1b2`, profile source `f2b2410fe652fbbf1963bbbbba5f9e5e1928f2bb177e5262d9edee30a99a101c`. Every owned path must admit today's analysis owner/privacy/membership/active source AND the stored original version/root before returning stored content or receipts. Export remains the complete owner collection, including retained historical rows.

Use the frozen `InitialFeedbackPlan`, `QualitativeSupport`, `InitialFeedbackRender` and retained-only native envelope schemas. Plan policy is `initial-feedback-plan-policy/1.0.0`, SHA `972b648ccc90b29c0c88fc504ac2746ab1489e17f05cfd2048cb487a2b38cc48`; content policy is `qualitative-content-support/1.0.0`, SHA `230f22333dd468f3bf78395b118330ec1ff78de18be9da5349356e84d0f6bd13`; writing IR stays `legacy-source-transforms/1.0.4`. The pure output retains `authority:'source_content_only'` and `ownedVersionProof:'not_provided'`.

All objects below are strict: reject unknown/duplicate fields, invalid UTF8, noncanonical UUID/SHA values, unsafe numbers and oversized envelopes. UUIDs/SHA256 are lowercase. UTC timestamps preserve the actual native microsecond token. `Usage` is null or `{inputTokens:string,outputTokens:string}`, each canonical decimal in `0..9007199254740991`; null is unknown, never zero. Counts/aggregates are canonical decimal strings, decoded with BigInt. `Lease` is the existing exact `{workerId,attempt,leaseFence}` and does not make queue attempt equal provider ordinal.

`PolicySelector` is exactly `{version,sha256}`. Native resolves an immutable technical policy; it never accepts caller prices, limits, model authority, currentness or support booleans. The full stored `PublicationPolicy` has `{version,sha256,provider,model,promptVersion,maxOutputTokens,attemptLimit,budgetPolicyVersion,supportVersion,supportSha256,planVersion,planSha256,writingSupportPolicyVersion,scoringInputProfile,planProfile}`. Provider is `openai`; attemptLimit is 1..3, captured once; budgetPolicyVersion is null only for the native-selected budget-off mode. Both profile objects are the actual frozen source profiles, not caller pins. The new policy descriptor/hash must be generated from actual source before code freeze; this document supplies no dummy digest or policy seed.

The immutable `Binding` is exactly `{schemaVersion:'initial-feedback-binding/1.0.0',analysisId,ownerId,organizationId,resumeId,resumeVersionId,scoringInputSha256,deterministicContentSha256,resultChecksum,sourceTextSha256,jobId,jobSha256,policy}`. Native derives all identities and bytes from the actual original scoring-input row and its deterministic result. scoringInputSha256 is its native input-binding digest; resultChecksum remains the original ordered-JS producer checksum, independently checked by Node. A none-job has both jobId/jobSha256 null. bindingSha256 is native SHA256 of this exact JSONB binding; Node treats it as opaque and validates the returned owned fields. It is never SHA256(JSON.stringify(binding)).

## RPCs and common records

The exact proposed signatures are:

```text
prepare_initial_feedback(p_analysis_id uuid,p_lease jsonb,p_policy jsonb,p_retry_after_attempt_id uuid) -> jsonb
claim_initial_feedback_dispatch(p_analysis_id uuid,p_lease jsonb,p_operation_id uuid,p_attempt_id uuid,p_binding_sha256 text,p_budget jsonb) -> jsonb
settle_initial_feedback_attempt(p_operation_id uuid,p_attempt_id uuid,p_binding_sha256 text,p_usage jsonb,p_error_code text) -> jsonb
finish_initial_feedback(p_analysis_id uuid,p_lease jsonb,p_operation_id uuid,p_attempt_id uuid,p_binding_sha256 text,p_completion jsonb,p_process_id text,p_request_id text) -> jsonb
read_initial_feedback(p_user_id uuid,p_analysis_id uuid) -> jsonb
read_initial_feedback_usage(p_user_id uuid,p_analysis_id uuid) -> jsonb
export_initial_feedback_records(p_user_id uuid) -> jsonb
read_initial_feedback_readiness() -> jsonb
```

Only metadata readiness may be service-readable at staging. All new data readers, mutators, exporter and private helpers remain denied, including service_role, until separately reviewed native/privacy/caller adoption. A successful source check is not an installed-catalog or activation claim. Future readiness separately checks exact producer/renderer/scoring guard bodies, attributes, FKs/triggers, ACLs, privacy/export and caller compatibility; it does not modify frozen base138, typed13, A12 or old score guards.

`Operation` is exactly `{schemaVersion:'initial-feedback-operation/1.0.0',operationId,analysisId,ownerId,organizationId,binding,bindingSha256,state,attemptLimit,attempts,publicationId}`. state is `open|published`; publicationId is nullable. Native UUIDs and one operation per analysis are enforced by uniqueness. A changed runtime policy never starts a second automatic operation. Existing operation policy is returned unchanged; intentional regeneration is outside this wire.

Each of at most three `Attempt` records is `{attemptId,ordinal,state,claimedAt,usage,errorCode,budgetAttemptId}`. state is `reserved|dispatched|known|held_unknown|failed|cancelled_before_dispatch|published`. claimedAt is null before dispatch and immutable thereafter. usage is null before/unknown after dispatch, not a fabricated zero. errorCode is null or `provider_failed|timeout|cancelled|invalid_output|unsupported_output|storage_failed|unknown`. budgetAttemptId is null unless the exact linked R03 attempt was actually admitted. No source/JD/proposal text enters operation/technical accounting records. Invalid input, denied access, stale/conflicting state and unavailable dependencies raise fixed SQLSTATE 22023/42501/P0C01/P0C03 respectively; no raw provider/SQL text is returned. Node exposes fixed invalid/not_found/stale/unavailable/cancelled errors; an uncertain mutation permits exact retry, never new dispatch.

`Context` is exactly `{scoringContext,deterministicResult,currentness,generationEligibility}`: actual existing bound LegacyScoringContext; actual exact LegacyScoringResult; currentness `current|historical`; eligibility `eligible|historical_inputs|source_resource_limit`. It preserves full original extraction/page arrays/JD, including the scoring producer's larger source limit. No canonical/JD-version IDs are invented before those products exist. The unchanged 4MiB scoring-context ceiling applies; no truncation.

## Prepare, replay and once-only dispatch

Prepare requires current owned access first, then resolves exact prior publication/operation before fresh lease/status, consent, rate, budget or transport construction. Its strict union is:

```text
{schemaVersion:'initial-feedback-prepare/1.0.0',status:'prepared',operation,attempt,context,dispatchAllowed:false,replayed:false}
{schemaVersion:'initial-feedback-prepare/1.0.0',status:'pending',operation,attempt:null|Attempt,context:null,dispatchAllowed:false,replayed:true}
{schemaVersion:'initial-feedback-prepare/1.0.0',status:'published',operation,publication,context:null,dispatchAllowed:false,replayed:true}
```

Only a newly prepared operation/explicit new attempt returns nonnull context. A reserved replay is pending, not permission to retry the provider. Lost/ambiguous prepare or claim responses are resolved by exact lookup; no timed reclaim. A new operation captures original binding/policy and allocates attempt ordinal1. Null retry selector only looks up/initializes. A nonnull retry selector must equal the latest native terminal known-failure attempt and may allocate maxOrdinal+1 only under its captured retry policy, current valid lease/input/consent and remaining native cap. The same selector replays the already-created next attempt. It cannot advance past reserved/dispatched/held_unknown attempts, treat a queue retry as a new provider ordinal, or retry a published result. No automatic retry loop is introduced by this wire.

Prepare may return a historical/resource-ineligible original context so deterministic-only publication remains possible. Fresh claim independently refuses it. AI-off workers may prepare metadata and finish deterministic-only without consent/rates/budget/provider; metadata reservation is not a budget reservation or provider claim.

Claim CAS requires `operation.state=open`, `publicationId=null` and this exact attempt in reserved state. A published operation can never regain dispatch permission. Claim response is exactly `{schemaVersion:'initial-feedback-claim/1.0.0',operation,attempt,dispatchAllowed:boolean,replayed:boolean,budget:null|AiBudgetEnvelope}`. Only the first atomic reserved-to-dispatched transition returns true. Every loser/exact replay returns false and must never execute, settle, release or mark the winner. Claim checks the actual current lease/fence, original and current source/JD/input equality, native policy/resource bounds, membership/privacy and actual current qualitative_ai consent in BOTH budget modes. Consent follows the actual user/purpose/policy semantics; do not invent an analysis-organization consent requirement or write consent for the worker.

With budget off p_budget is null and operation claim is still mandatory. With budget on p_budget is the exact `{p_user_id,p_organization_id,p_request}` of the existing ai_budget_claim_dispatch call. Native binds operationId to this operation, exact existing reserved attempt/model/prompt/surface/payload/reservation and captured policy. The operation CAS and old budget claim happen in the SAME transaction, or neither wins. The adapter intercepts only that generic claim and returns its unchanged strict budget envelope. Generic R03 settlement debits once; feedback settlement mirrors technical usage and never debits the shared pool again. The provider idempotency key is a versioned framed digest of actual owner/org/analysis/operation/attempt/binding/model/prompt identities, never a bare analysis/client UUID.

## Raw response, accounting and failure lifecycle

The enabled path uses ONE SDK response from a dedicated versioned raw boundary with the admitted immutable original inputs; it preserves the old APIs. The raw result is `{schemaVersion:'initial-feedback-raw/1.0.0',output:unknown,refused:boolean,finishReason:string|null,usage:ProviderUsage|null}`. Output is the bounded unmodified decoded generation JSON, before writer resolution or grounding; the safe-usage observer fires before JSON/schema validation or rejection. This boundary does not make a second provider request. Intercept safe usage immediately on its raw response/error, before refusal/schema/content validation and before a budget wrapper can replace the error. Await technical settlement before exposing output or validating/persisting content. Unknown/invalid/missing counters settle null and retain a hold. No `Number(value ?? 0)`, string coercion, clipping or fabricated zero. All known invalid/refused/over-reservation output is charged; R03 overrun fences remain.

Do NOT compile `runQualitativeAi(...).prose`: that helper filters through groundQualitativeProseWithSupport, and OpenAIQualitativeTransport.execute first invokes resolveWriterProposals, whose flatMap drops unknown/duplicate source IDs. Neither lossy result is an original observation. Parse the original ProseGenerationSchema candidate, resolve EVERY writer sourceId against the actual original buildRewriteSources result without changing order, and preserve all category/writer text. Any unknown OR duplicate writer reference refuses the WHOLE generation, with usage retained; never invent an original string or drop an entry. The resulting full QualitativeSourceProse has the same writer indices and exact owned original quotations. Pass this losslessly resolved rawProse into compileInitialFeedbackPlan ONCE. Reuse its one actual core assessment/recordedObservation and exact complete retained plan/render; do not assess a second time, reindex compressed output, retry raw text, or silently omit retained parts. Malformed/refused/truncated JSON or invalid writer references produce no fabricated QualitativeSupport observation. They instead have a nullable capture-only `GenerationFailure={schemaVersion:'initial-feedback-generation-failure/1.0.0',reason:'refused'|'truncated'|'malformed_json'|'schema_invalid'|'source_reference_invalid',rawResponseSha256:null|sha256}`; hashes record Node observations, not native proof. A generation failure and a full core observation are mutually exclusive. Valid assessed rawProse retains original indices/rejections even when compilation is unavailable. No raw resume/JD/provider prose is logged.

Settle response is exactly `{schemaVersion:'initial-feedback-settlement/1.0.0',operationId,attemptId,bindingSha256,state,usage,errorCode,replayed}` with state `known|held_unknown|failed`. It requires exact stored static identity and an actually dispatched attempt, but no current membership, consent, lease or candidate-content read. Initial known usage with errorCode null records accounting only, not success. A later fixed terminal error may complete that pending outcome without changing known counts. Exact repeats are idempotent; changed known counts or conflicting fixed terminal outcome refuse. Null never clears known usage. A late observed known value may fill unknown once without clearing the terminal error or reviving dispatch. A fixed terminal failure with null usage may permit deterministic-only publication, but the held_unknown accounting reserve remains and cannot admit a retry. Retry eligibility requires observed known usage plus the captured retry policy. No expiry/refund/reclaim of unknown/crashed attempts. Operator evidence/reconciliation and retention approval remain separate dependencies.

## Atomic finish and deterministic-only preservation

Completion is one strict union:

```text
{kind:'assessed',plan:InitialFeedbackPlan,observation:QualitativeSupport,generationFailure:null}
{kind:'deterministic_only',reason:'ai_disabled'|'historical_inputs'|'source_resource_limit'|'pre_dispatch_unavailable',plan:null,observation:null,generationFailure:null}
{kind:'deterministic_only',reason:'provider_unavailable'|'invalid_output'|'unsupported_output'|'attempts_exhausted',plan:null,observation:QualitativeSupport|null,generationFailure:GenerationFailure|null}
```

The second variant requires p_attempt_id null and no attempt EVER dispatched: every claimedAt is null. pre_dispatch_unavailable preserves saved checks after a consent/rate/quota/dependency refusal without inventing those events or usage. If an earlier attempt was claimed, the third variant must reference its real terminal attempt; it cannot be relabeled as pre-dispatch. Deterministic-only finish atomically publishes/closes the operation and changes every never-dispatched reserved attempt to cancelled_before_dispatch, so prepare -> partial -> late claim cannot dispatch. It never changes another winner or a claimed unknown hold. It can close only never-dispatched metadata; it cannot release an unrelated budget hold. The third requires the exact recorded terminal attempt and preserves its known/null usage, error and any actual observation. Once an observation is recorded, no null/different value can replace it. Provider failure before schema assessment legitimately has null observation; preserve its actual GenerationFailure if one exists. Null cannot erase an already captured failure. Published outcomes cannot be downgraded by a late storage_failed settlement; an ambiguous finish is resolved by exact publication lookup/replay before failure handling. If content access/lease is lost after dispatch, technical settlement remains allowed but candidate publication/capture is refused; do not claim an observation was persisted then. Deterministic-only carries no owned retained proof and cannot overwrite an assessed publication or accept late provider output into it.

Fresh assessed finish requires the exact current attempt in known state with observed known usage and null errorCode, not a failed/unknown/terminal attempt, and independently reloads original immutable input/result and current owned source/job/lease/privacy/consent. It invokes the frozen private renderer on actual original source and supplied plan, derives actual retained support/mapping, and checks complete retained correspondence to the capture. The FULL unchanged Node observation is capture-only, stored with its actual native captureSha256; rejected raw hashes are not independently proved. The owned support envelope is explicitly retained_output_only, with actual native binding/plan/render/support digests. No supplied supported/current/grounded boolean or digest substitutes for reconstruction.

Acquire analysis then queue, bounded current/original source and immutable snapshot/result locks with the existing nonblocking owner/privacy protocol, then operation/attempt/publication and compatible result/writer slots; reverse source/FK paths must not wait. Every fresh return rechecks required actual state under those locks. Exact prior publication is resolved after current/original access but BEFORE fresh lease/JD/consent checks. Finish returns exactly `{schemaVersion:'initial-feedback-finish/1.0.0',status:'published',publication}`. A repeat must match the original operation/attempt/binding AND exact completion body; new process/request audit IDs do not change identity. An altered completion conflicts, never rebases. Process/request IDs are bounded printable audit values as in the scoring-input contract.

One transaction stores immutable publication/full capture/retained proof, exact native receipt, compatible analysis_results/writer_drafts/linked legacy run, and transition. Reuse the existing closed qualitative/partial producer with values derived by native, or a separately reviewed equivalent factory. Any old false return, support/projection mismatch or final guard failure RAISES and rolls back every candidate row; never return error JSON after a partial commit. Existing unmatched result/draft/run slots conflict. AI evidence-v2 guards and initial uncalibrated refusal remain intact. Copy numeric score, traces, parser/rules/normalizer/taxonomy and original JS checksum from the actual original deterministic row; neither model ratings nor policy changes own numbers.

`Publication` is exactly `{schemaVersion:'initial-feedback-publication/1.0.0',publicationId,state,reason,binding,plan,recordedObservation,generationFailure,ownedSupport,prose,compatibility,receipt}`. State is assessed/deterministic_only. Assessed reason is null; deterministic reasons are the exact completion reasons. For assessed, plan/observation/ownedSupport/prose are nonnull and compatibility comes from native render plus unchanged deterministic fields. For deterministic-only, plan/ownedSupport/prose are null, recordedObservation/generationFailure preserve the actual mutually exclusive attempt capture if any, and compatibility uses existing deterministic partial semantics. The native receipt is `{schemaVersion:'initial-feedback-receipt/1.0.0',operationId,attemptId:null|uuid,publicationId,analysisId,ownerId,bindingSha256,publicationSha256,resultSha256,writerSha256:null|sha256,runId:null|uuid,createdAt,replayed}`. Digests are actual native values; a missing partial writer is null, never an empty invented writer. Stored receipt replay normalizes only replayed. No publication can claim currentness by timestamp alone.

## Owned read, quota and privacy coupling

Read is the strict union below after current/original source access and exact publication/projection correlation:

```text
{schemaVersion:'initial-feedback-read/1.0.0',status:'available',currentness:'current'|'historical',publication}
{schemaVersion:'initial-feedback-read/1.0.0',status:'legacy_unbound',analysisId,reason:'original_input_or_publication_missing'}
{schemaVersion:'initial-feedback-read/1.0.0',status:'pending',operation,attempt:null|Attempt}
```

No currentness/strength is inferred from quote presence, nonempty legacy content or a supplied digest. Available compares actual original input/deterministic row and compatible result/writer digests. Changed current JD/source is historical; unavailable current comparison refuses rather than guessing. Legacy-unbound results remain visibly unverified, with their ordinary owned read separate. A pending operation never fabricates an empty assessed publication.

The new usage reply has exactly `{schemaVersion:'initial-feedback-usage/1.0.0',profileVersion,usageSha256,ownerId,organizationId,analysisId,periodStart,periodEnd,legacyUnlinkedTokens,canonicalTokens,initialFeedbackTokens,totalTokens,unknownClaims}`. Native derives owned organization and current UTC month. One snapshot partitions legacy analysis_ai_runs EXCLUDING authoritative linked A12 canonical AND A13 feedback run IDs, all A12 claimed known usage, and ALL new claimed feedback known usage including rejected/partial/unpublished attempts. This includes an actual retained pre-compatibility A12 run linked by canonical operation.run_id. Linked run IDs are unique and must prove exact owner/org/analysis/operation-or-attempt/usage consistency; an inconsistent link refuses. Exclude proven links across ALL claim/publication months before selecting legacy rows for the requested month, so a late compatibility projection never adds a second charge in a different month. Count a linked attempt only in its immutable claimed_at month, even when the legacy projection is written/settled later. Claimed null usage contributes to unknownClaims, not zero known usage. Total is the exact sum of the three disjoint known components. No fallback to oldcounter on absent/error/malformed response.

Node requires exact owner/org/analysis/profile/component totals and the actual current UTC month at completion; crossed month, elapsed deadline, unknown claims or unsafe numeric representation refuses generation. This is an observational quota read, NOT an atomic monthly cap. R03 supplies the shared hard reservation/debit boundary when enabled. Before A12 OR A13 adoption, both callers must use the separately versioned shared counter including this partition; frozen A12 counter/profile and legacy get_organization_ai_tokens_used are not silently rewritten. Ordinary legacy runs without a new link remain counted. The old Number(tokensUsed ?? 0) path is forbidden in the new mode.

Export must include complete owned operations/attempts/publications/full captures/proofs with fixed row/byte bounds, no currentness/status/feature-flag omission. Candidate stores cascade with actual account/analysis/source references; technical claimed usage must remain recordable after withdrawal/source removal under the separately admitted minimal metadata lifecycle. No invented retention period or indefinite-PII clearance. Paired strict privacy export/erasure, exact forward profile/admission and real native role/concurrency/rollback verification are required before adoption. This document is a wire freeze proposal, not evidence that those implementations or runtime behaviors exist.
