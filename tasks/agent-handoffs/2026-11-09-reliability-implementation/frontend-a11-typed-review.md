# A11 typed review surface

Implemented as a reusable callback component; production routes and the existing typed pause are unchanged. Owned files are `TypedAuthoringReview.tsx`, its new DOM test and this handoff. Exact source/test hashes are in the private packet's `frozen-code.json`.

The component consumes the actual typed workspace/proposal/command/receipt interfaces through type-only imports. It requires explicit clause and complete contribution selection, shows the entire before/after and server rationale, and keeps listings and reconstructed date fragments explanation-only. Numeric score/delta remain unavailable. Native labelled controls, fieldsets, existing design tokens and disclosure patterns preserve keyboard access without a layout redesign.

Owning-route callback contract:

- `onRequestProposal(selection)` returns the real proposal and exact accept/reject command pair. It must map disabled/no-change outcomes honestly rather than inventing a proposal.
- `onDecision(command, reviewAcknowledgement)` receives the unchanged original command. The visible acknowledgement is fresh human input, separate from the prospective acknowledgement already inside the wire command. The owning route must validate the complete receipt against that command before returning an applied result; browser correlation is not server authorization or native hash proof.
- `onUndo(receipt)` receives the exact recorded receipt. The component links its actual version even when it is not the current head; it does not claim undo succeeded merely because the callback returned.

Selection edits/reverts, changed input bindings and history restoration invalidate review. Synchronous barriers prevent duplicate request/decision clicks. Ambiguous failures retain the original command for manual exact retry. A definite review-again refusal is superseded only after an explicit successful new preview.
