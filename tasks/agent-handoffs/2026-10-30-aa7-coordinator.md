## Concrete local design for AA070 review

- Authenticated standalone `/latex` page: paste supported single-file LaTeX, choose an example/page size, compile, preview and download PDF. No source persistence or analyzer calls. Manual PDF upload remains an independent user action.
- Support a documented strict subset with fixed article class, an explicit package/command/environment allowlist and English/Latin fonts. Reject arbitrary includes, files, custom macro definitions, encoded control sequences, bidi controls, unsafe links and unsupported packages before dispatch. Never claim full Overleaf compatibility.
- XeLaTeX inside an immutable-ID Docker image, fixed build-time packages/fonts and no runtime installation. No host TeX fallback. Build downloads public dependencies only; recognition/compilation receives synthetic/local data only and has no network.
- Each request gets a disposable non-root container with read-only root, no host mounts/socket, network none, capabilities dropped, no-new-privileges, private namespaces, 2 CPUs, 512 MiB memory/no extra swap, 128 MiB volatile scratch, 64 PIDs, 64 open files, 8 MiB file cap, 10 CPU seconds and 20 seconds wall time. Maximum 48 KiB source, 5 MiB PDF, 10 pages, 2 active compilations. Source/PDF use bounded stdin/stdout; logs discarded, fixed safe diagnostic codes only. Timeout/cancel must kill/remove the exact owned container and verify cleanup.
- Server-owned image configuration, default-off converter flag, same-origin authenticated POST, bounded request/rate admission, no tokens/environment credentials passed into compiler. Reject malformed PDF, active content, overflow, missing glyphs and failed parse-back. Structural checks do not establish tagged-PDF or assistive-technology certification.
- Rollback disables the converter flag and cleans only run-owned containers; resume checker is unchanged. Host compromise/TeX CVEs and formal accessibility/representative evidence remain release-review risks.
