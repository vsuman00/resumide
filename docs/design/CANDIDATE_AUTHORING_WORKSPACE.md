# AA5 candidate-controlled authoring workspace

Local engineering under [ADR-0014/E-005](../decisions/0014-aa5-local-engineering-sequencing.md). Formal Gate AA5 remains open.

The private analysis diagnostics page embeds the editor when `AUTHORING_ENABLED=true` alongside `SCORING_V2_ENABLED=true`. Its forms post to `/analysis/:id/author`; GET shares the same analysis workspace. Both flags default off. The diagnostics endpoint remains read-only. Native forms work without JavaScript. Saves and review actions require verified owner identity, same origin, bounded strict input, active source/membership, absence of a pending deletion and the expected canonical version. Historical views disable editing. Busy actions expose a status and disable controls.

The outline covers actual sections plus any imported facts not assigned to an entry. Section title changes and fact corrections preserve stable IDs and create child versions. Corrections clear source support and remain unconfirmed; confirmation is an explicit candidate declaration. The uploaded source and all prior canonical versions remain immutable. Finding links target existing textareas; source/structure findings without editable evidence explain why prose cannot repair them. Critical source reviews precede required, other and preferred reviews. Only the first five appear in the main queue; remaining findings remain available. Impact points and quantitative effort estimates are unavailable.

Suggestion patches bind one contribution fact, canonical version, section, entry, affected rule/requirement IDs and exact source fact IDs. There is one bounded replacement operation, a rationale, clarification needs and explicitly uncalibrated confidence. Acceptance recomputes the deterministic permitted reconstruction; arbitrary prose, added facts, unsupported IDs, whole-document replacement, cross-section/stale patches, new measurements/seniority and unsupported domain/locale patches are rejected. These conservative local patterns do not provide unrestricted generative rewriting.

Clarification asks about result, measurement, scope, method and personal ownership. Blank answers do not mutate content. Confirmed answers update the existing contribution fact with typed labelled text and become candidate-confirmed in one transaction; the immutable authoring ledger retains the exact question kind, answer, owner, base/result versions and time. This is candidate-provided provenance, not verified source accuracy. No standalone new fact type or extracted source assertion is invented.

XYZ uses the candidate's result, measurement and method. Action-impact-context and action-scope-result alternatives need result and scope and do not require a metric. Missing/unknown measurements cannot make XYZ ready. Writing diagnostics flag punctuation, adjacent repetition, length and unsupported numerical/seniority additions without assigning a prose score. Domain quality and factual strength remain subject to validation and candidate review. Every acceptance requires explicit review of the proposed text.

`apply_authoring_action` holds the existing resume row lock and delegates canonical changes to the validated CAS saver. Clarification/acceptance edit and confirm atomically: failure of confirmation rolls back the intermediate version, audit and ledger. Rejection appends a decision without changing the head. Idempotency keys bind exact commands, including rejected/undo decisions. Undo restores the pre-action state as a new version, including skipping an intermediate edit/confirm pair; explicit restore requires an ancestor. Compare uses the existing immutable version read model. A failed or stale save retains the submitted correction and request key, offers exact retry, and permits a new correction against the current version only through explicit review. Unrelated unchanged input controls retain unsaved drafts; changed facts refresh their values.

The ledger is owner-readable with active-source/membership/deletion RLS, immutable even to privileged updates, and writable only through the service RPC. Deletion cascades through owner/source/analysis/version references. Full canonical/JD/authoring collections export through a bounded stable MVCC snapshot, avoiding mismatched references during concurrent saves. Populated restore verifies ledger content, RLS, triggers and reconstructed scoring diagnostics. Hosted migration/deployment is deferred.

Projected diagnostics are labelled before acceptance; actual diagnostics read persisted canonical versions. Numeric scores and deltas are null while AA4 policy/calibration remain unapproved. No arbitrary improvement claim or employer acceptance probability is shown.

The proposal interface has no default provider. Explicit injected transports receive only the selected candidate-confirmed contribution/version context, untrusted-data instructions, an abort signal, timeout and bounded strict output validation. Provider failure/timeout produces no patch or mutation. Local UI patterns continue to function without a provider. The locked known-synthetic harness compares exact and hallucinating injected adapters, not actual models. No cheaper/faster real model is selected, and edit usefulness, representative domain quality and human candidate-review acceptance remain unavailable pending authorized evaluation.
