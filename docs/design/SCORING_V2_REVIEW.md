# AA4 scoring diagnostics and legacy presentation

Status: local engineering implemented under owner-approved E-004. Numeric policy activation and formal Gate AA4 remain open.

The private `/analysis/:id/score` read model combines an immutable document-evidence attempt, a selected canonical resume version, a selected JD requirement version, an exact draft policy ID and server-owned declared page metadata. It creates a deterministic fingerprint and diagnostics; it writes no score/history rows. The existing canonical/JD histories and privacy export remain the replayable inputs. A populated restore test regenerates the same diagnostics. Declared page metadata is checked live; changing it changes the input fingerprint and page observations. This read model is not an archive of previously published scores.

`SCORING_V2_ENABLED` defaults to false. Enable it only for local review alongside the evidence/canonical/JD flags. No migration or deployed worker setting changes are needed for these diagnostics. Authentication precedes privileged reads; ownership, membership, active source, deletion requests and head versions are checked before and after computation. Historical selectors are UUIDs; other parameters and client weights/policies/identity are rejected. Private responses use no-store and noindex headers. Writes receive 405. Removed sources and cross-owner versions receive 404, moving/stale heads 409, invalid inputs 422 and unavailable storage 503.

All three authoritative dimensions are null: ATS Compatibility, Required Job Alignment and Preferred Job Alignment. Calibration, weights, coverage floors and bands are unavailable. Recovery coverage describes where text was observed, not calibrated extraction accuracy. Confirmation records owner review but cannot clear calibration/source-quality blockers. Unsupported domain/locale inputs stay unsupported, and Application Readiness remains disabled.

Six bounded technical traces describe recovered pages, recognized sections, contact candidates, date order, bullet duplication and qualified layout evidence. Rule credits are diagnostic observations, never activated policy contributions. Layout remains not evaluated when no qualified geometry is available. Illustrative weighted normalization is isolated from production scoring and tests the AA0 60/75/coverage examples, justified inapplicability, unknown critical checks and zero denominators.

Alignment preserves required/preferred/contextual/unknown importance. Exact typed requirements group once independently of supplied dedup labels. Conflicting importance, inferred/model-proposed clauses, unpaired dates, unsupported equivalents and missing evidence remain unknown. Confirmed full ISO date ranges linked to software roles use the union of overlapping intervals; ambiguous years and Present dates do not create inferred duration. Listed skills never prove proficiency. Sponsorship exclusions require eligibility review rather than being treated as inapplicable qualifications. Candidate observations are explicitly separate from evaluated requirement states; all positive alignment remains not evaluated pending source/domain/policy validation.

The UI shows version references, blockers, recovered observations, source excerpts and pinned fact/JD links, with at most five repair priorities. It contains no v2 gauges, fabricated point gains, employer acceptance probabilities or readiness aggregate. Automated browser checks cover keyboard navigation, axe, narrow-screen reflow, source/version presentation and privacy. Human comprehension evaluation remains unavailable.

New model requests use a strict score-free prose schema with exact resume quotes. Unmatched quotes are excluded. Provider output persisted in AI-run history has no numeric rating fields. The existing feedback envelope keeps zero compatibility placeholders for qualitative categories, explicitly tagged `deterministic_baseline_no_model_ratings/1.0.0`; the UI/report hides these placeholders and shows cited prose. The overall baseline comes entirely from existing deterministic rules. Completed historical records are never reprocessed; original values, dates and recorded versions remain unchanged and are labeled legacy, without v2 comparison. Unknown historical scoring versions remain unknown. The original numeric output schema remains available for historical compatibility only.

The offline validity harness measures deterministic replay, synthetic-name invariance, repeated clauses, skill/bullet stuffing, injection rejection, coverage and latency. A separate strict measurement helper implements tie-aware Spearman, seeded case bootstrap percentile intervals, MAE, RMSE and per-segment coverage/error. Mathematical synthetic tests validate these estimators; no real reviewed ratings are claimed. Benchmark engineering mode passes its known synthetic checks; release mode emits a blocked receipt and exits 1 while representative/expert/domain/calibration/comprehension obligations remain open.
