# R08 queue lease fencing

Status: source implemented; SQL UNEXECUTED. The migration has not been parsed, applied or exercised against PostgreSQL. No worker, queue, provider, database, Docker or browser operation ran. Root owns config/integration and the final combined gate; frontend owns the queue client/runner and its separate unit evidence.

The CLI-created migration `20261110080810_lease_fencing_and_verification_scope.sql` adds an opaque UUID `lease_fence` to `analysis_jobs`. Four service-only v2 RPCs use an empty search path. Claim returns exactly `schemaVersion: analysis-job-lease/2.0.0`, `analysisId`, `attempt`, `runAfter`, `leaseFence`, and `leaseExpiresAt`. Each claim rotates the UUID, including same-worker reclaim. Heartbeat/completion/release require analysis ID, worker, attempt and fence matching an unexpired lease. Time is rechecked with the database clock after lock acquisition; expired leases cannot be revived by a stale transaction timestamp.

The fixed signatures are `claim_analysis_job_v2(text,integer)`, `heartbeat_analysis_job_v2(uuid,text,integer,uuid,integer)`, `complete_analysis_job_v2(uuid,text,integer,uuid)` and `release_analysis_job_v2(uuid,text,integer,uuid,integer,text)`. Parameters are `p_worker_id,p_lease_seconds` for claim; otherwise `p_analysis_id,p_worker_id,p_attempt,p_lease_fence`, plus `p_lease_seconds` or `p_retry_delay_seconds,p_error_code` where applicable. Claim validates ASCII worker IDs up to 128 characters, leases of 1–3600 seconds and at most three attempts. Mutation mismatches return false; invalid claim arguments raise a fixed `22023` error. No shared-project scoped claim or production test scope is supplied.

Both v2 sweep and selection filter fresh owner membership and exact active resume/version ownership before their 100-candidate bound, then lock analysis→job and revalidate membership/source under shared locks. Source locks use SKIP LOCKED to avoid waiting behind source-first retention while holding its analysis. The latest current-source document-evidence envelope must match analysis/owner/version/checksum/schema and uncalibrated, scoring-ineligible metadata to count as a review handoff. Such handoffs are not claimed or dead-lettered. A current owner can complete a live handoff without changing its review status. Completed, partial, failed and rejected terminal results can clean up their owned live queue row; authorized cancellation deletes/invalidate its job. Membership revocation, source deletion, a foreign token or a reclaimed attempt denies mutation.

Release retains the non-null fence across queued retries. Existing legacy worker RPC signatures/grants and NULL-fence behavior remain available, but every legacy claim, sweep, heartbeat, completion and release is constrained to `lease_fence IS NULL`. Both claim paths and legacy release use analysis→job ordering. Direct queue DML is revoked from service/client roles; current application writes use definer RPCs or authorized cascades. Enqueue-on-conflict cannot rewrite an existing fenced row. Authorized cancellation/privacy deletion remains allowed; a fence must not obstruct erasure.
