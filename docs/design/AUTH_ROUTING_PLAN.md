# AUTH-ROUTING: AI connections and funding preferences

The [November 22 provider contract](../decisions/0022-auth-provider-contract.md#ai-funding) covers the separate API credit benefit for eligible ChatGPT subscribers.

Status: **PLANNED; source and documentation review only**. Updated 2026-10-17. Base: `fab804841183169a8d9a2a6a3fd1b702f979565d`. No implementation, provider inference, owner acceptance, or release approval is established here.

## Scope and dependencies

Follow the [coordinator assignment](../../tasks/agent-handoffs/2026-10-17-auth-coordinator.md), [constraints](../../CONSTRAINTS.md), [architecture](../../ARCHITECTURE.md), [identity decision](../decisions/0002-managed-postgres-identity-and-private-storage.md), [AI decision](../decisions/0003-versioned-deterministic-scoring-and-bounded-ai.md), [T031](../../tasks/todo.md#t031-implement-user-session-and-personal-organization-slice), and [AA5 authoring plan](../../tasks/accuracy-authoring-plan.md#9-phase-aa5-same-page-authoring-and-grounded-writing). The application session remains Supabase-owned. Google sign-in and ChatGPT identity sign-in must both resolve to the existing application user and personal organization. Neither sign-in selects who pays for inference. AUTH-CHATGPT owns verified identity and plan-permission acquisition; this plan owns the connection consumed after that flow. Email equality must never link credentials or establish ownership.

## Current source evidence

- `app/routes/api.analyze.ts` authenticates, checks same origin and rate limits, then records `candidate-ai-v1` consent. `analysis-ingestion.ts` finds the personal organization and invokes `create_queued_analysis`. Neither accepts an AI connection or funding choice.
- `analysis-worker.ts` runs extraction, deterministic scoring, then qualitative review. `qualitative-stage.ts` uses organization token totals and deployment-wide `OPENAI_API_KEY`, `OPENAI_MODEL`, and cost settings. It stores the selected model and prompt version, but has no user connection resolver or execution-time connection/permission check.
- `qualitative-ai.ts` calls `chat.completions.parse`, uses Zod structured output and `max_completion_tokens`, and returns a grounded prose object. Its timeout races the promise without cancelling the underlying request. The stage's input hash includes inputs and prompt version, but not funding, connection, model, or schema version.
- `jobs.ts` and `worker-runner.ts` provide leased retries and heartbeats. The qualitative call does not currently receive the worker abort signal. A job lease does not serialize OAuth refreshes shared across jobs.
- `privacy.ts`, `privacy-worker.ts`, and `privacy-operations.ts` already support consent and export/deletion. They do not yet define credential export exclusion or connection revocation. `egress-policy.ts` accepts only the OpenAI API base; OAuth endpoints need separate reviewed allowlists.
- Existing tests cover grounded output, refusal, timeout, provider outage, partial feedback, worker leases, ownership, and privacy. Those are source-inspected tests, not new test results.

## Verified provider boundary

Official OpenAI documentation reviewed 2026-10-17 separates identity from optional plan usage. Website sign-in is a limited commercial trial requiring registration. Hosted Resumide must receive relevant access; open-source/local examples do not establish hosted permission. Keep connection controls unavailable until that prerequisite is recorded. [Website sign-in](https://developers.openai.com/siwc/website), [quickstart](https://developers.openai.com/siwc/quickstart), [local integration availability](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt).

The selected account's catalog uses `models`, `visibility`, `display_name`, and `slug`. Plan requests use OAuth with `/v1/responses`, `store:false`, and `stream:true`; only a completed terminal event establishes success. Failed, incomplete, and interrupted streams must not commit prose. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

The preview rejects `max_output_tokens` and several ordinary Responses parameters. Use instructions/developer messages rather than an explicit system-message item. Catalog membership alone does not prove strict-schema support. The reviewed plan docs do not establish compatibility with this application's schema or its mandatory token cap. A separate adapter and approved output-bound solution are prerequisites; substituting an OAuth token into the current adapter is insufficient. Abort/byte/time bounds reduce local exposure but cannot establish a provider-side token or charge ceiling. Keep plan inference disabled if the required bound cannot be enforced. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Refreshes must be serialized for the same session, using the registration's issued client ID and latest rotating credentials. Remote revocation may fail and needs an honest local-disconnect result. Usage limits and permission failures require user recovery, with no payer change. [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

## Proposed minimal contract

1. Store one active AI preference per application user: `fundingMode` (`app_budget` or `chatgpt_plan`), nullable `connectionId`, selected `modelSlug`, preference version, and consent-policy reference. No choice is inferred from login method. A Google-authenticated user may separately connect an eligible ChatGPT account. Identity-only ChatGPT sign-in creates no inference grant. Disconnected plan funding stays unavailable until the user acts.
2. A connection records an opaque ID, application owner and organization, provider, validated provider subject/workspace/client association, granted capabilities, status, expiry, and credential generation. Keep identity-provider tokens separate from inference credentials. Permit one selectable connection initially; never overwrite another registration based on matching email. No BYO API-key entry or multi-provider framework is included.
3. A separate server-only credential record holds authenticated ciphertext for access/refresh and any required retained ID token, encryption key version, nonce/tag, and generation. Bind authenticated encryption to connection/owner/provider. Keep keys outside the database and repository; web callback and worker privileges are narrowly separated. Browser/RLS reads return metadata only. Key rotation, backup recovery, and credential-destruction retention need operations review before persistence ships.
4. At enqueue, validate active membership, ownership, consent and provider grant, then atomically snapshot funding, connection ID, credential-independent grant generation, model slug, capability-policy version, prompt/schema version, and source version into an analysis AI execution record referenced by the queue's analysis ID. Queue payloads carry references, never credentials. A saved preference affects future work; it cannot switch an existing job's payer or account. Existing jobs need an explicit legacy app-budget policy version, not a silent reinterpretation.
5. Before discovery, dispatch, retry and result commit, recheck the job owner, organization membership, deletion state, current consent, connection status and grant generation. Resolve credentials by owner plus connection ID, never by ID alone. Reject foreign/stale references. Token refresh changes credential generation; revoke/reconnect changes grant generation and invalidates queued work. A new grant requires a new explicit request.
6. Discover with the selected connection, cache privately by connection/grant with a bounded expiry, and clear on reconnect/revoke. Display only discoverable models intersecting a server-approved capability policy. Validate the chosen model again at dispatch. Require strict output contract, grounding, input/output bounds, supported transport, and locked quality evidence. Never accept a browser-supplied URL, arbitrary model, or claimed capability. Do not pin a public API model name as universally eligible.
7. Keep existing `QualitativeAiTransport` as the narrow normalized output boundary. A proposed `ChatGptPlanTransport` assembles bounded SSE output internally, validates terminal success and full schema, then returns output and usage for existing grounding. No partial text reaches stored feedback. Malformed events, refusal, injected facts, missing usage and cancellation have typed safe outcomes. Requests must disable hidden SDK retries so queue policy owns attempts. AA3/AA5 injected adapters remain offline unless separately approved; this work does not activate them.

## Concurrency, failure and privacy

Use a database lease and compare-and-swap on connection credential generation for refresh across web/worker instances. Waiters reread the winner's credentials. Do not hold a database transaction across the network call. Reject late writes after revoke, deletion or lease loss. A crash after provider rotation but before persistence may require reconnect; do not replay a possibly consumed refresh token indefinitely.

Record an AI execution key over analysis/source version, funding, connection/grant, model, prompt/schema and capability policy. Preserve it across retries; reject an idempotency key reused with a different snapshot. Fence result commits by active job lease and execution generation. Store one accepted result and deduplicate usage receipts. Neither an idempotency header nor a local unique key proves exactly-once provider billing. Track dispatch/unknown/completed outcomes; avoid automatic redispatch after an ambiguous timeout until the approved provider replay policy is known. Propagate abort through the transport on timeout, lost lease, deletion or revoke; already-dispatched content cannot be recalled.

Retry bounded transient network/5xx failures only where replay is safe. Rate limits obey provider recovery/Retry-After and local limits; exhausted plan usage is surfaced for user action. A refreshable expiry permits one coordinated refresh, while invalid grants require reconnect. Permission loss, unapproved models, schema failures and refusal never switch to app-paid calls. Preserve deterministic evidence and existing score-withholding rules; record qualitative work as unavailable/partial with a bounded public reason. Switching to app funding requires an explicit fresh request, app entitlement and consent checks. Keep deployment kill switches, per-owner concurrency and abuse limits for both funding modes. App-priced USD estimates must not be reported as ChatGPT-plan charges or remaining allowance.

Disconnect immediately invalidates the grant, clears selection, cancels queued work and prevents further use. Attempt remote revocation only when the registered integration has a documented, supported revocation capability; report whether it was confirmed. Otherwise destroy local credentials and direct the user to disconnect in ChatGPT Settings; do not invent an endpoint. Any bounded encrypted revocation retry must be governed by a retention deadline; after destruction, offer the provider settings recovery path. Sign-out, identity unlink, AI disconnect and account deletion are separate actions with explicit semantics. Deletion immediately blocks access, coordinates revocation and credential erasure, and documents backup expiry. Export preference, consent, safe connection metadata and funding/model execution provenance; exclude tokens, ciphertext, keys and login hints. Do not log raw SSE errors, authorization URLs, provider identities, prompts or resume/JD text. Audit opaque IDs and safe codes only.
