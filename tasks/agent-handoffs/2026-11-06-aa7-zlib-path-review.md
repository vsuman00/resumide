## Defect and production paths

The [Debian advisory](https://security-tracker.debian.org/tracker/CVE-2026-76844) identifies stale caller input after gz_write encounters a failed OS write. On installed1.3.1, reaching the overflow requires clearing that stream's error with gzclearerr and then another gzip-file write. The [upstream repair](https://github.com/madler/zlib/commit/df84af25dc1942490e1d1c899a07619152a46148) resets pending input on error. Ordinary memory inflate/deflate APIs do not enter this gzip-file writer.

## Scope and review conditions

The proposal applies to this immutable image and fixed candidate-LaTeX entrypoint. dlopen/dlsym imports in Python, ctypes and several libraries are recorded explicitly. The audit covers four actual ldd graphs plus47 module ELFs themselves, not every possible future module/plugin dependency or arbitrary native/Python code execution. Absence of imports does not prove resistance to arbitrary RCE. Reassess if entrypoints, initialization mode, plugins, Python execution, dependencies or gzip failure-recovery code change. Do not generalize this result to the other zlib CVEs or suppress raw scanner matches.
