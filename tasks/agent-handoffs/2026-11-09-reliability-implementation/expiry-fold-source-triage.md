## Conservation and replay requirements

Shared quota and R03 cost are separate measures. The shared reader validates links across all months before partitioning actual legacy runs, A12 usage and A13 attempt usage. Retained `legacy_unlinked` runs add once; linked retained runs require their surviving exact typed accounting proof. A13 publication deletion is supported by the real retirement proof. Dedup uses actual run IDs, not input hashes: two runs with one hash still count twice. Live/retained conflicts refuse before org/month filters.

At fold, preserve that validated shared partition once, using legacy `run_created_at` UTC month and typed `claimed_at` UTC month. Preserve R03 spent tokens/cost separately using each attempt's stored `period`; moving either measure to capture, settlement or expiry month is wrong. Never add R03 token totals to shared usage. Preserve unresolved technical exposure, typed unknown claims and unreconciled overage blocks separately. R03 `reserved`, `dispatched` and `held_unknown` are not interchangeable: undispatched release needs a serialized proof; no unknown amount becomes zero merely because identity expires.

R03 pools currently combine opening spend, settled spend and live reservations by organization/month. `ai_budget_blocked` also checks excess usage without a reconciliation event. Deleting attempts/events without preserving these effects can reopen capacity. Keeping an attributable pool/opening projection or its subject-bearing evidence indefinitely is not an anonymous fold. Rebuild from remaining authorized state and install the accepted global hold in the same transaction as removal; do not subtract first and rely on a later worker.

Retained aggregates may have only original UTC-month keys and unlinked numeric safety measures. They must not retain an owner/org/op/attempt/run/actor/request ID, nonce, hash, exact event time or per-subject fold receipt. A month row can merge contributions atomically; per-run dedup must happen while its personal row still exists, followed by deletion in that transaction. Retrying an ambiguous commit finds no eligible personal row and cannot debit again. It must not recreate it to return a replay certificate.

The current legacy `get_organization_ai_tokens_used(org,p_since)` has arbitrary-since, all-run semantics. Month-only, org-free aggregates cannot reconstruct an exact historical organization total or split a month at an arbitrary timestamp. Affected reads must return fixed unavailable; they must not expose/add a global total to that organization or omit folded charges. Current-month shared/provider gates use the accepted global block through UTC period end for known charges whose 720-hour deadline precedes month end. Unresolved exposure remains blocked beyond identity expiry pending controlled aggregate reconciliation. Expiry never refunds it.

Current due-legacy checks already fail closed rather than filter expired charges. Static R03/typed settle/outcome/finish APIs have no disposition-deadline closure today. Before erasure they need a single expiry linearization rule under the same locks: a permitted result commits before expiry or loses; late evidence after selector removal refuses without recreating identity. Source-backed replay is now tied to actual immutable parents and OP2 domains. Build is account-only: purging its selector while the original Auth identity remains usable permits the same nonce to be recreated, so Build purge requires actual account/session admission closure. Parent restoration is a separate replay hazard, not cured by a UUID codec.

Proposed names below are new contracts, not existing APIs. Use one private month-only aggregate relation and an operator-only due-fold entry; no register-only per-subject receipt store. ## Scheduler, Auth and restore dependencies

`runRetentionSweep` and `scripts/run-retention.ts` process resume-object cutoff work using `RETENTION_DAYS`; they do not sweep accounting deadlines. Package scripts provide a one-shot retention command, and CI artifact retention is unrelated. No accounting deadline scheduler or missed-deadline monitor was found. Add a separate bounded due-disposition worker/entry script and deadline health contract, with DB time, safety-margin wakeups and hard failure reporting. No finite batch/history cap proves a maximum completion time; resource/statement deadlines and an actual drain/cadence acceptance test are required.

The existing restore verifier checks checksum/ownership only. The restore runbook has isolation but no deletion replay, session quarantine enforcement or independent monotonic floor. Add `backup-restore.ts`, its tests, `scripts/verify-restore.ts` and the restore runbook as a later bounded slice paired with an external floor adapter. A floor inside the restored database is rollbackable. Its independent authority must be wired before a purge can erase the journal; an eternal owner/hash deletion list is forbidden.

Actual session revocation, Auth deletion, personal-org deletion/transfer, old manifests, exact object cleanup and audit/request/foreign-actor cleanup remain adoption dependencies. Restrictive ledgers and organization owner cascades make blind Auth deletion unsafe. Failure is a deadline breach, not permission to extend clocks.
