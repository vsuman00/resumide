## Result and interfaces

`provider-attempt.ts` now owns one linked AbortController, deadline and caller listener. Pre-aborted requests do not execute transport work. Deadline/caller cancellation settles a bounded failure, then aborts the linked signal passed to the SDK request. Both winner and post-await checks prevent accepting late output from a transport that ignores abort. Timers/listeners are removed on every settled path. Caller-provided abort reasons are not forwarded as log/error text. This is an in-memory attempt boundary, not a durable spend reservation or remote-cost refund.

Both transport request types accept optional `signal?: AbortSignal`; so do `runQualitativeAi` arguments and the existing `generateGroundedRewrite` request. The HTTP rewrite service passes its actual `request.signal` at the existing call. No qualitative-stage edit was needed for its current wrapper deadline; lease-loss and broader stage/request fencing remain R09 work. Existing HTTP error-response mapping is unchanged.

`QualitativeAiFailure(code, retryable = false, usage = null)` adds a typed readonly nullable usage field without a new required constructor argument. Only safe nonnegative integer input/output counters survive; the copied counter object is frozen. `AI_CANCELLED` is nonretryable; `AI_TIMEOUT` is retryable. Errors retain the fixed safe message, enum code and retryability. A reviewed compatibility rule additionally preserves only numeric integer HTTP status 100–599 as a nonwritable optional property. No provider body, message, headers, cause or arbitrary metadata is copied. Already typed failures retain their usage/status through classification and catches. Installed SDK timeout detection uses its actual `APIConnectionTimeoutError` constructor; its `.name` is merely `Error` in this SDK.

The two SDK paths use raw `.chat.completions.create` with the same model options, messages, token limits, strict structured schema/name and idempotency key. Explicit `store:false` is added; it was previously absent. Existing `maxRetries:0`, SDK logging off, redirect rejection and constructor timeout remain. The optional linked signal is SDK request metadata, never a provider prompt/body field.

Safe observed usage is read before refusal/content/finish/schema handling. Only a stop completion with valid JSON and the existing schema can succeed; valid-looking truncated/content-filter/other non-stop output is rejected. Known usage survives refusal, malformed JSON, schema failures and truncated output. Missing, negative, fractional, nonnumeric or unsafe counters are unknown/null, never fabricated zero. Genuine reported zero/zero remains known. Actual transport and high-level service success require known usage; otherwise they fail `AI_OUTPUT_INVALID` with usage null. This conservative admission keeps current durable callers from persisting fabricated counters while R03's unknown-cost reservation/reconciliation is still absent.

No prompt, grounding policy, source quotation, deterministic scoring or actual candidate content changed. The legacy exported `analyzeResume` has an old separate SDK client; the coordinator found no served/importing callers and explicitly kept it outside this packet. No claim is made that every future AI surface now shares this attempt policy.
