# Recovery of interrupted tracked upload cleanup

CR-R17-S04 recovers positively acknowledged, unadopted uploads from the existing account-deletion hold. An interrupted HTTP request could previously leave the privacy worker with an inventory and no way to resume exact object cleanup.

The new claim RPC uses the privacy worker's live request, attempt and owner lock. It checks the immutable inventory again, locks up to four eligible uploads and moves prepared entries to `cleanup_pending` before returning any object keys. The filter excludes missing acknowledgements, legacy rows, adopted uploads, active or recorded queued work, noncanonical keys and any supporting analysis, resume, version or job record. It also excludes keys still referenced by another version. The worker validates every key and ID, checks the acknowledged Storage identity and requires exact-key absence. The completion RPC rechecks the claim, inventory, row state and recorded object ID. A fresh claim can recover when the prior worker removed the object and lost its completion acknowledgement.

The four regressions failed before the worker integration. All 102 focused cases and 6,784 application tests across 323 files passed. Formatting, typecheck, lint and both builds passed. Lint reported four existing warnings.
