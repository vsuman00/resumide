# Pinned worker image CVE triage

Status: targeted private triage, 2026-11-06. The image remains unapproved for release. No raw finding, severity or vendor status was changed, suppressed or removed. This review made no image, package, source, policy or dependency changes and ran no container or exploit.

## Evidence and limits

[The complete scanner receipt](AA7_IMAGE_CVE_20261106.json) retains the offline Trivy 0.76.2 results for pinned image `sha256:600c3815bdf12a4e3df6d332c0aea11685fd122f0fc3240b7be3c802fd23bf4f`, Linux/arm64. It reports four critical and 269 high package/CVE matches, with 3,632 matches across all severities. Package presence is evidence of a match, not proof of an exploitable application path. Conversely, a missing proof of reachability is not proof of safety.

This bounded review covers the four critical matches and the ten high matches for `python3-pypdf2`. Other high findings remain untriaged. Library membership in the exact Landlock closure was not independently established in this review; the build script derives library access from `ldd`, and no absence or reachability claim is inferred merely from a library name. The supervisor and PDF checker were inspected directly. The preserved runtime receipt proves resource/isolation controls, not removal of package vulnerabilities.

## Directly reachable PDF parser

[`supervisor.py`](../../scripts/latex-runtime/supervisor.py) imports `inspect_pdf` before handling a job. [`inspect_pdf.py`](../../scripts/latex-runtime/inspect_pdf.py) imports `PdfReader` from `PyPDF2`, constructs it with `strict=True`, resolves indirect objects and traverses the trailer, xref objects and page structures. The parser therefore processes generated PDF bytes on the normal success path. Candidate-controlled LaTeX is upstream of those bytes; the fact that the app does not accept a PDF upload on this route does not establish that parser defects are unreachable.

The current checker does not call PyPDF2 text extraction or its `xfa` property. Text extraction is performed by the separate Poppler `pdftotext` process. These observations help distinguish advisory preconditions but do not remove package findings. Existing source/PDF byte limits, memory/CPU limits and the outer wall timeout bound some denial-of-service consequences; they do not patch the parser or prove all malformed-input behavior safe.

All ten high matches concern installed `python3-pypdf2` `2.12.1-3+deb12u1`. The scan reports no fixed package version for any of them. Debian's [PyPDF2 source-package tracker](https://security-tracker.debian.org/tracker/source-package/pypdf2) still lists the Bookworm package as vulnerable; the upstream fixes below belong to maintained `pypdf`, not an available fixed PyPDF2 package in the frozen image.

## Bounded remediation recommendation

1. Preserve image `600c…`, this failed security receipt and all prior runtime results. Keep production disabled; neither passing containment tests nor this triage supplies CVE acceptance.
2. Prioritize the directly invoked PDF parser. Prepare a separate candidate image using a hash-pinned maintained `pypdf` release that has fixes for the reviewed issues, or reviewed backports if a maintained distribution package is chosen. Upstream [documents the PyPDF2-to-pypdf migration](https://pypdf.readthedocs.io/en/stable/meta/history.html). Merely changing the import or selecting the newest version is not sufficient: review its current advisories, dependencies and API compatibility first. No particular version is adopted here.
3. In that candidate, reassess unnecessary build/header and unused runtime packages. Prefer a small runtime stage over broad package removal that breaks TeX, fonts or parser dependencies. A newer base or backported GLib/SQLite version is an image/policy decision, not a silent update to the accepted snapshot.
4. Regenerate package/license and runtime/closure hashes, scan the candidate with the same retained database and an updated database when appropriate, and compare findings without suppressions. Rerun the PDF active-content/bounds corpus, malicious-input/isolation/resource matrix, six example/paper combinations and relevant browser flows. The parser swap must preserve fail-closed semantics, cancellation and cleanup.
5. Record remaining findings with exact affected components, vendor evidence and uncertainty. The 259 other high matches are not cleared by this targeted review; broader high/critical triage and the separate running-kernel review remain necessary before any release decision.

No build or dependency edit was performed. This is the first bounded triage result, not full security closure.
