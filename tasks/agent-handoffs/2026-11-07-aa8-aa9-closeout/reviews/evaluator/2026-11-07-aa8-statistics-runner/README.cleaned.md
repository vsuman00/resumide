# AA8 statistics and locked evaluation runner

The four files in `review-manifest.json` implement numeric evaluation and the locked measured-ledger workflow. They are ready for coordinator integration. They do not run application callbacks themselves or establish a representative population result.

`evaluateStatistics(input)` requires every expected document and every configured metric slot. A slot can be explicitly `null`: its aggregate and affected segment cells retain the full denominator, report `withheld` with a missing count, and fail readiness. Unknowns are never zero-filled or omitted. Other measured cells remain reportable. Missing keys or documents are rejected.

Numeric cells use exactly 10,000 deterministic whole-cluster percentile resamples and two-sided 95% intervals. Aggregate draws preserve members across segments; each segment uses its own deterministic draw plan. Cluster resampling does not prove sample representativeness or nominal finite-sample coverage. Rank uses average ranks for ties; undefined replicates are counted and block the interval. All-success or otherwise degenerate bootstrap samples cannot earn a numeric validity pass. Exact-zero safety is an observed incident check, without a population-error guarantee. Latency and cost policies concern document means, not p95. Synchronous weighted work is capped at 8,192 units before draws; larger runs require a separate execution-budget decision.

`runLockedEvaluation(input, reader, context)` invokes the actual partition API before the reader and revalidates the current partition and calibration authority after it resolves. The context supplies the current manifest and verifies the exact server-generated calibration payload hash, proposal/version/input/lock binding. A JSON readiness flag alone grants nothing. All ten required metrics and all locked sources/hashes/segments are bound. Connected components combine every declared person, employer, template, source-family and near-duplicate dependency; ledger callers cannot substitute independent cluster IDs.

The runner assesses a supplied measured ledger. The application orchestration owns execution and provenance of those measurements. Engineering numeric readiness is separate from representative readiness. The latter additionally requires eligible independent-human partition and calibration evidence, a sample-justification reference, and a trusted in-process authorization for the exact evaluation. Unit fixtures exercise that authorization branch without claiming that a real representative evaluation happened. Release readiness remains outside this module.

Verification: final targeted suites passed 24 tests (14 statistics, 10 runner). Scoped strict TypeScript, ESLint, Prettier and diff checks are recorded individually in `final-checks.json`. Tests cover deterministic cluster draws, cross-segment dependencies, bounds, rank degeneracy, missing segments, zero incidents, null coverage, actual partition/calibration integration, denied or changed authority, incomplete/hash-drifted observations, overlapping cluster components, and separately authorized representative branches.

Retained failures: an initial test-file syntax typo prevented collection and was corrected; an added representative-fixture branch initially omitted its trusted authority argument and failed before calibration, then passed after that fixture correction. No product assertion or threshold was weakened. The earlier pre-withheld manifest is retained. Read-only copied dependency hashes are in `baseline-inputs.json`; they are not owned changes.

No Docker, database, provider, browser, deployment or AA7 revalidation was performed. Coordinator integration and the actual synthetic application workflow remain separate verification tiers.

Method reference: [SciPy bootstrap documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html) describes percentile intervals and degenerate bootstrap limitations. This implementation uses existing JavaScript dependencies, not SciPy.
