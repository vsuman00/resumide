# A12 missing writer workspace bootstrap

Design only, 2026-11-15. Root assigned this file alone while it closes the coupled A13/A12 compatibility gate. No source, test, schema, policy, migration, service or production setting changed. This is a source-confirmed missing producer path, not a database observation or native execution result. Earlier application tests seeded an existing summary draft and cannot establish fresh-workspace availability.

## Source path

[The canonical reader](../../../supabase/migrations/20261114181344_canonical_rewrite_operations.sql:341) requires an existing owned writer_drafts row of kind summary with SELECT STRICT. Its context contains that row's actual ID, timestamp and projection hash. [The request schema](../../../app/lib/server/canonical-rewrite-contract.ts:77) then requires draftId and expectedDraftUpdatedAt; neither may be manufactured for a missing row. The canonical finish only updates that existing row by its original timestamp.

There are five writer_drafts INSERT statements across the old migrations. They belong to legacy persist_completed_analysis, persist_qualitative_analysis and persist_partial_analysis, including their later replacements. The taxonomy migration's deterministic scorer still does not create a writer row. [Evidence extraction](../../../app/lib/server/extraction-stage.ts:325) persists document evidence and returns. [Scoring](../../../app/lib/server/scoring-stage.ts:87) and [qualitative generation](../../../app/lib/server/qualitative-stage.ts:83) intentionally do not run the legacy scored path for uncalibrated evidence. Canonical import/regroup/admission adds no writer slot. Thus source does not show a creator for a fresh evidence/canonical analysis's summary draft.

[The score loader](../../../app/routes/analysis.score.tsx:185) currently catches a failed workspace read and supplies no replacement. This is safer than inventing a draft, but it does not provide initialization. Preserve the numerical/evidence guards; legacy scored persistence is not a bootstrap mechanism.

## Preferred next contract: explicit ensure-missing operation

Add a separate authenticated POST resource, proposed `/analysis/:id/rewrite/workspace`, with exactly canonicalVersionId and requirementVersionId UUID fields. Accept bounded native forms with duplicate/unknown-field refusal, same-origin/authentication checks, private response headers and the existing scoring/authoring/canonical-rewrite feature gates before admin IO. The session supplies owner identity. This action creates empty storage only: no provider, AI consent audit, rate-budget claim, generated prose or score. It must not create an AI operation or imply permission for later generation. Whether the initialization RPC is admitted remains an explicit source/native activation decision; do not grant a new mutator merely to make the UI render.

Proposed native RPC: initialize_canonical_rewrite_workspace(p_user_id uuid, p_analysis_id uuid, p_selection jsonb, p_policy jsonb). p_selection has exactly the two selected version IDs; p_policy is the existing server-derived rewrite policy, not client authority. The server creates no caller-supplied draft ID, timestamp, version or head.

Within one transaction:

1. Admit current owner, membership, privacy/retention, active root/source and the exact analysis/source tuple using the established lock order. Check the actual bootstrap capability/profile and owned selected canonical/JD proofs. Both selections must equal current heads for this fresh initialization; stale selectors refuse without mutation.
2. Lock the same root/analysis scope used by existing canonical rewrite and legacy writers. Check the summary slot. If present, validate its owner/org/analysis/kind and projection, then return it unchanged. Never blank, retag or refresh its timestamp, even when it contains prior legacy or canonical content.
3. If absent, insert only the exact empty legacy-compatible projection {summary:null,bullets:[]} with server-owned IDs and timestamps. UNIQUE(analysis_id,kind) is the final duplicate barrier. Use insert-on-conflict-do-nothing followed by an exact owned reread if needed; no conflict-update. A conflicting foreign/corrupt row fails closed rather than being adopted.
4. Return an initialization result with created true/false and the actual canonical rewrite context read after insertion. The existing reader supplies the real row ID, canonical UTC timestamp and native projection hash. A new row has no rewrite version/head and genuinely has revision zero; this does not invent a persisted publication. No canonical content, analysis result, scoring state, accepted fact or prior operation changes.

Creation is idempotent by the existing unique slot. This protocol promises ensure-current-workspace semantics, not an immutable original initialization receipt: a retry returns the actual existing current row or a stale-selection conflict, never a fabricated original timestamp. No provider dispatch occurs during either attempt. If exact byte-for-byte initialization receipt replay is later required, it needs a distinct persisted command ledger and privacy coverage; do not smuggle it into the existing generation operation domain.

A successful initialization only refreshes the displayed workspace. The candidate must then explicitly request generation with a new operation ID and the returned real tokens/consent. It must never overwrite or rebase an already pending generation request. Existing generation exact replay remains before fresh CAS and is unchanged.

## GET and consumer state

GET remains read-only. A separate owned workspace-state reader, proposed read_canonical_rewrite_workspace_state with the existing user/analysis/selection/policy arguments, returns either the existing context or an explicit initialization_required descriptor. Missing is emitted only after actual owner/source/canonical/JD checks; a generic not_found/P0002 is not proof of a missing slot. The missing variant has real selected source/version identities and initialization capability, with no fake draft ID, timestamp, native projection hash or rewrite binding.

The score consumer shows an explicit initialization action only for that admitted missing state. Historical selection, privacy failure, unavailable proof and denied capability remain distinct. After initialization the empty projection has no supported saved prose; do not label it a current generated draft or an earlier legacy recommendation. Existing nonempty drafts remain visible/copyable according to their actual bound or unbound status. GET must not insert, call a legacy scored persist, bulk backfill analyses or silently initialize during the first generation attempt.

## Alternative: bootstrap only at first publication

A versioned absent-draft request/binding could avoid an empty storage write: prepare records true absence, claim dispatches once, and finish inserts the summary row, immutable publication/head and receipt atomically. It needs a real absent/present draft union, strict version dispatch, absent-row CAS and correlated output IDs, plus repository/service/UI changes; the old required UUID/timestamp request cannot represent it honestly. Failed generation would leave no slot. This is a coherent wider alternative, but it changes more protocol surfaces and is not the smallest prerequisite repair. Never emulate it with a zero UUID or synthetic time.

## Bounded vertical sequence and acceptance

Preferred native/server leaf, at most five files: forward CLI migration containing the owned state reader and explicit initializer/readiness closure, new bootstrap server contract/repository/resource helper, thin POST route, focused actual-handler/source-contract test, handoff. Root owns route registration and migration ordering. Any new routine uses explicit ACL policy; old scoring guards/base138 and frozen migrations remain unchanged. Initializer stays denied/default-off until its own admission, not inherited from a broad naming prefix.

The paired consumer leaf, at most five files: actual score loader, initialization control/panel, their two focused tests and handoff. This leaf makes the missing-workspace state and explicit POST reachable; a disconnected RPC alone does not close the gap. Existing privacy export already includes writer_drafts; if the frozen implementation introduces any new store, add its export/deletion companion before adoption rather than assuming coverage.

Meaningful checks start with a real owned fake store containing no summary row, not a preseeded draft. GET reports missing with zero writer/bootstrap writes; explicit POST inserts one empty row; repeated/concurrent initialization returns one real slot without updating content/time. Existing empty, nonempty legacy, bound canonical and historical drafts are preserved. Wrong owner/org/source, deletion/retention policy, stale canonical/JD heads, malformed fields, uniqueness races and denied readiness fail closed. An ambiguous POST retry cannot generate prose, allocate duplicate slots or rebase a pending generation. The next explicit generation must use the actual returned ID/timestamp, then preserve existing claim/usage/final-CAS/replay behavior. Native transaction/role/race/cleanup verification and real consumer/provider acceptance remain separate and unexecuted here.
