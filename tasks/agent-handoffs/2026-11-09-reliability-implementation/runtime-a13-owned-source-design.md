## Existing authority and the missing input record

| Actual relation | Existing binding and payload |
| --- | --- |
| `analyses` | `id`, owner/org, `resume_version_id` FK, nullable `job_id` FK, status, request/idempotency identities. Initial work requires `qualitative_review`. |
| `resume_versions` → `resumes` | Version owner/org, file `checksum`, bytes/media/page metadata; root owner/org and active status. File checksum is stored provenance, not a fresh storage-byte verification. |
| `analysis_extractions` | PK/FK `analysis_id`, owner/org, full `extracted_text`, `text_checksum`, page count/texts, warnings, duration, extractor version, created time; nullable evidence graph/native layout. Text permits 200,000 characters; native legacy pages are bounded to 1–20. |
| `analysis_deterministic_results` | PK/FK analysis, owner/org, score, parse view, rule trace, keyword coverage, `input_text_checksum`, `result_checksum`, parser/ruleset/normalizer/taxonomy versions and created time. |
| `jobs` | Owned ID/org, mutable title/description/company and update time. No immutable selected-JD reference exists on the legacy deterministic row. |
| `analysis_jobs` | PK/FK analysis, worker, expiry, attempt count 0–3, fence, schedule/error/deadletter metadata. The server supplies worker/attempt/fence; these are not evidence authority. |

[scoring-stage.ts:40](../../../app/lib/server/scoring-stage.ts:40) hashes the deterministic payload with `JSON.stringify`; that checksum includes the resume text checksum and keyword-derived results, but **not the exact JD text or a JD snapshot hash**. Current feedback reads even fewer fields. Capturing today's job at feedback prepare cannot prove an older deterministic result used that job. Do not backfill that relationship from current rows.

The first forward prerequisite is a real owned scoring-input reader plus an atomic bound deterministic-persist wrapper. The reader returns the actual extraction and job snapshot/native digests. The wrapper rechecks those exact inputs under locks, calls the unchanged deterministic producer, and records an immutable input binding in the same transaction. A legacy row without that record remains explicitly unbound for JD-dependent findings. Matching extraction and deterministic text checksums is necessary but insufficient.

The actual source-independent rule IDs are `contact.email`, `contact.phone`, `sections.experience`, `sections.education`, `sections.skills`, `dates.parseable`, `bullets.experience`, and `length.reasonable`: they consume parse-view/word-count data, not JD matching. Their existing outcomes can remain legacy source observations when full text/checksum and producer versions match. A detected date is not tenure; a section is not verified experience. The length rule includes heuristic ATS wording, which must not become a new factual guarantee. `keywords.coverage` and the weighted overall score depend on JD. Do not relabel that overall score as source-only, remove its JD weight, or manufacture a replacement score. Calibration/unsafe-input gates still apply to every number.

## Bound context before canonical or typed JD exists

Use a discriminated `legacy_extraction` envelope: actual owner/org/analysis/root/source IDs, file checksum, exact extraction fields and UTF8 text checksum, opaque SQL-native extraction digest, deterministic producer checksum plus a separate native deterministic-content digest, and the exact owned job ID/title/description/native digest. Bind the new scoring-input record when present. Canonical version, typed JD version, heads, confirmation and evidence-attempt IDs are null/absent according to this explicit variant; do not invent them. Capture source and JD text only in the protected immutable publication/input store, never technical operation rows, logs or telemetry.

The native reader recomputes the extraction text SHA, requires the stored text and deterministic input checksum to agree, and compares all captured source/JD/deterministic fields again at finish. Timestamp equality alone is insufficient. `result_checksum` remains its original JS-producer checksum; `jsonb::text` SHA is a separately named native digest, never claimed equal to `JSON.stringify` SHA.

The released pure support module is intentionally `authority=source_content_only`, `ownedVersionProof=not_provided`. Its source/policy hashes, part decisions, operations and code-point citation ranges are useful correlation and validation output, not native authorization. A new owned-publication envelope must retain that sidecar unchanged and separately carry independently reconstructed native support. Never accept its `retained`, state, anchor IDs or hashes as proof. The latest released backend checkpoint is `qualitative-support.ts` SHA `602ba4c5f2be916e85e891dbc9e168083db6e978bb821bce9404a66fa777f666`, policy `qualitative-content-support/1.0.0` SHA `230f22333dd468f3bf78395b118330ec1ff78de18be9da5349356e84d0f6bd13`; its actual descriptor is in the backend `resumide-a13-feedback-core-6yfiudzo/policy-actual.json` packet.

Do not truncate 200,000-character extraction text to satisfy the frozen IR's 100,000-UTF16 source ceiling. Explicit resource-unavailable is honest. Preserve current 512 anchors, 16 citation anchors, 73 assessments, 65,536 input-JSON bytes, four tips/category, four writer bullets and existing projection caps. Build/cache the whole admitted source IR once; charge shared aggregate work and output bytes, including native reconstruction. Any expanded capability requires an actual versioned counterpart.

The existing initial path must retain [hasUncalibratedEvidence](../../../app/lib/server/evidence-scoring-guard.ts) and the three native `block_unreviewed_evidence_scores` triggers. Any v2 attempt blocks legacy deterministic results, AI runs and analysis results even after confirmation. A future canonical/post-review prose-only invocation therefore needs its own admitted entrypoint/publication path with numbers withheld. It cannot be implemented by removing the initial guard, filling fake canonical IDs, or falling back to extraction after a failed canonical read.

## Proposed operation and transaction seam

Use separate versioned source/scoring-input and feedback profiles, not edits to base138 or A12's support policy. Fresh worker RPCs take a strict server lease tuple plus analysis and policy/operation identities; owner/org are derived and rechecked from actual rows. Proposed feedback names are read/prepare, once-only claim, technical settle and atomic finish under an `initial_feedback/1` protocol. Freeze exact DTOs with the actual pure core before implementing their native plan.

- Resolve ownership without locks, acquire the common owner mutex before object locks, take the fresh VOLATILE R19 shared privacy admission, then lock analysis → job, membership and exact source/root/job/extraction/deterministic rows in the reviewed order. Existing `lock_analysis_stage_lease` takes analysis → job and uses nonblocking privacy admission; do not introduce an object → waiting-owner inversion. No lock or database transaction spans provider execution. READ COMMITTED/read-uncommitted-equivalent only; failed/cancelled deletion requests are inactive, other states block candidate work.
- Current access precedes exact prior receipt/status lookup. Prior replay checks the original stored operation/request/attempt binding before fresh heads, rates, consent or provider work. Do not require a still-live queue lease merely to return an already committed owned receipt after completion; static original identity is not permission for fresh work. New prepare/claim/finish require the actual unexpired worker/attempt/fence and eligible status. A nonnull new context is admission to continue; only the winning claim grants dispatch.
- Use a new namespaced feedback logical operation, rather than collide with legacy qualitative budget operation `analysisId`. Each actual provider attempt has a separate durable attempt identity. SQL selects the budget ordinal; queue attempt is not that ordinal. Both budget modes require operation CAS. Budget-on claims operation plus the existing budget dispatch in one transaction. Exact/ambiguous same-attempt retry never redispatches or refunds; separately permitted retries stay within captured policy and preserve old holds.
- Technical settle stores safe known decimal usage or null plus fixed errors, retaining counts before later budget accounting can replace a provider failure. It remains recordable after membership/consent/deletion changes using the exact static technical identity; no candidate snapshot is read or written there. Metadata retention/erasure needs explicit admission, not an invented period.
- Finish re-proves the captured source/JD/scoring-input/native digests, lease, privacy and consent, then independently reconstructs the closed support plan and deterministic findings from owned rows. No supplied support boolean or digest substitutes for this. Copy unchanged deterministic values; never accept model numbers. Publish immutable source/support/projection/receipt and the compatible initial legacy result/draft together. If the old persist returns false, raise inside the enclosing write transaction: returning false after inserts must not commit partial output. Refresh lease/privacy after all locks and before commit. Stale/unsafe/cancelled work preserves prior content and recorded usage; an ambiguous finish response is recovered through exact replay.

Old public legacy persist and direct DML remain bypass/cutover considerations. A new writer is default-denied, with metadata readiness distinguishing schema integrity from executable grants. Adoption must explicitly close those bypasses; this design does not silently revoke old producers or claim whole-worker enforcement.
